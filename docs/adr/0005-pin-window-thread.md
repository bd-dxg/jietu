# 5. 贴图窗口统一主线程模型 + 非全局的窗口内快捷键

- **Status**: Accepted
- **Context**: M2b 贴图（PIN-1~6）需要两种触发路径：
  1. 截图编辑器内 F3/工具栏按钮：把**选区（含标注）**贴为屏幕置顶窗口——数据产生在覆盖层线程，但覆盖层线程生命周期随截图结束而退出；
  2. 非截图时全局 F3：把剪贴板图片贴屏（主线程热键响应）。
  另有一个交互期观察：早期把「切贴图边框」实现为**无修饰键全局热键**（`RegisterHotKey`），用户实测按 Y 会吞掉所有程序的 Y 输入（SYS-2 已提示过的风险真实发生）——需要规避。
- **Decision**:
  1. **贴图窗口统一由主线程创建**：覆盖层线程把裁剪图（含屏幕坐标）拷贝到 `GlobalAlloc` 载荷（`u32 w + u32 h + i32 x + i32 y + RGBA`），`PostMessage` 主窗口自定消息（`WM_PIN_FROM_EDITOR`），主线程 wndproc 建窗后 `GlobalFree`。窗口句柄、`PINS` 列表、消息循环全在主线程，天然串行无竞态；贴图生命周期不受截图层影响。
  2. **截图期间临时撤销全局贴图热键**：F3 在覆盖层内走「贴选区」，若不撤销，`WM_HOTKEY`（主线程）与 `WM_KEYDOWN`（覆盖层线程）会同时触发（一次贴剪贴板、一次贴选区）。截图开始 `UnregisterHotKey(PIN)`，overlay 线程结束 `PostMessage(WM_OVERLAY_DONE)` 重注册。
  3. **贴图窗口内的边框/辅助快捷键不是全局热键**：配置存键值后由模块 static 下发各贴图窗口，窗口聚焦时 `WM_SYSKEYDOWN | WM_KEYDOWN` 匹配（无修饰键也不抢占系统）；窗口级 `ImmAssociateContext(NULL)` 禁用 IME 保证输入法开启时字母键仍直达窗口。
- **Consequences**:
  - 更容易：跨线程边界只有一个自描述载荷消息（数据自持、接收方负责释放）；数量/关闭管理只需主线程一组 `Mutex<Vec<HWND>>`；无修饰键快捷键不再有抢占风险（局部作用域，用户可随意设 Y）。
  - 更难：载荷内存生命周期要严格配对（锁内仅拷贝、解锁后建窗弹窗避免模态重入）；「边框切换同步默认配置」需要贴图窗口 → 主窗口再发一条消息（`WM_PIN_BORDER_CHANGED`）由 App 写回 `config.toml`；窗口内快捷键对已存在贴图即时生效靠 static 配置下发。
